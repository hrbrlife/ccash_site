Architecture Questions

The CCASH platform enforces a 4-layer NFT hierarchy — a cryptographic chain of trust from root to leaf:

  1. Master NFT: Root authority, controlled by threshold signing. The sovereign key.
  2. Reseller NFT: Print Edition from Master. Can issue License NFTs to platform installations.
  3. License NFT (pNFT): Per-installation authority. Issues credential NFTs to verified users.
  4. Share NFT: Per-domain access tokens - up to 10,000 per License. The leaf of the tree.

Every operation on the platform traces its authority back through this hierarchy. No NFT, no authority. No exceptions.

A Grain is the fundamental isolation unit in Sandstorm/Melusina OS. Each grain is a sandboxed application instance with its own append-only journal store, capability set, and lifecycle. Think of it as an indestructible, self-contained process that remembers everything.

The CCASH platform uses two grain types:

  • Station Grains (orchestrators): long-lived components that manage multiple workflows and participants
  • Instance Grains (workers): one per entity, one per workflow, isolated and sovereign

Grains communicate via Cap'n Proto RPC through the Powerbox. No HTTP bridge. No shared databases. Pure capability security.

Cap'n Proto is a zero-copy serialization protocol - data is read directly from the wire format with no encoding or decoding step. We use it for inter-grain RPC communication on FD3, enabling native Sandstorm integration without an HTTP bridge.

Our Cap'n Proto schemas define the capability interfaces for core platform operations, compliance verification, and governance actions.

The Powerbox is the inter-grain capability sharing mechanism. When one grain needs to grant another access, it doesn't share a password or API key - it offers a capability through the Powerbox.

The flow works like this:

  1. A grain publishes a Powerbox offer (e.g., a specific API capability)
  2. Another grain requests the capability via Powerbox claim
  3. Claim token is converted to a persistent sturdyRef
  4. The sturdyRef survives restarts and enables cross-session, cross-grain communication

Capabilities are fine-grained and revocable. Each grain receives only the capabilities it needs for its specific role.
