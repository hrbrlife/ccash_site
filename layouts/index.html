Architecture

Built for Regulated Operations

CCASH is not a monolith. It is a capability-secured grain architecture — every component isolated at the OS level, every interaction mediated by cryptographic authority.

CCASH provides pre-built legal entity frameworks designed for regulated financial services. Series LLC architecture provides legal isolation between operating compartments while maintaining operational efficiency through a single administrative umbrella.

Series LLC architecture. Each operating compartment exists as its own Series with separate assets, liabilities, and participants — providing legal isolation while maintaining shared administration.
DAO LLC structures. Blockchain-native governance enabled through legally recognized entity types, with full statutory recognition under applicable law.

Go + HTMX Native Stack

Every component runs as a Go binary compiled to native code. No interpreter, no VM, no container overhead. HTMX delivers server-rendered HTML fragments — no SPA, no client-side routing, no JavaScript framework churn.

Native performance. Go compiled binaries with zero-copy Cap'n Proto serialization on file descriptor 3 (FD3). No HTTP bridge between components.
Server-rendered HTML. HTMX delivers interactive experiences without client-side frameworks. Every interaction authenticated at the capability level.
2

Grain Architecture

The CCASH platform uses a grain-based architecture where every component is an isolated process with its own journal store, capability set, and security boundary.

Station grains are orchestrators — long-lived components managing multiple workflows and participants across the system.
Instance grains are workers — one per entity, one per workflow, isolated and disposable. Each with its own journal store.
3

Journal-Based Storage

Every grain has an append-only journal store. Data is encrypted at rest with AES-256. Append-only logs enable deterministic replay for audit and disaster recovery. GDPR right-to-erasure is handled via cryptographic shredding — delete the encryption key, and the data is gone.

Deterministic replay. Full state reconstruction from journal logs for audit, forensic analysis, and disaster recovery.
Retention policies. Configurable retention periods with automated purge. Seven-year default for regulatory compliance.
1

NFt Authority Hierarchy

The CCASH platform enforces a 4-layer NFT hierarchy — a cryptographic chain of trust from root authority to per-user credentials. Every operation traces its authority back through this hierarchy.

4-layer model. Master NFT (root authority) → Reseller NFTs (delegated authority) → License NFTs (per-installation authority) → Share NFTs (per-domain access tokens).
No bypass. Every operation on the platform requires the appropriate NFT authority. No exceptions.
2

Capability Security

The Powerbox is the inter-grain capability sharing mechanism. Grains don't share passwords or API keys — they offer capabilities through the Powerbox. Capabilities are fine-grained, revocable, and auditable.

Powerbox offers and claims. Grains publish capability offers; other grains request and claim them. Claims become persistent sturdyRefs for cross-session access.
Least privilege. Each grain receives only the capabilities it needs. A Broker grain gets placement authority, not admin access. A compliance grain gets verification authority, not modification rights.
3

Defense in Depth

Every action passes through multiple authentication layers. No single layer is sufficient — all must agree before any operation proceeds. Compromise one layer and the others remain.

Wallet signature proves identity at the cryptographic level.
NFT verification proves role authorization — you must hold the right NFT for the action you are requesting.
Grain isolation ensures you can only reach components you have been granted access to.
Powerbox capabilities prove inter-component authority with persistent, cross-session access.
